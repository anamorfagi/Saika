# Датасет характера Сайки

Материалы для дообучения (LoRA/QLoRA) локальной модели под характер Сайки —
цель: закрепить и усилить то, что уже работает в `server/persona.py`, а не
придумать характер заново.

## Характер (источник правды: `server/persona.py`)

Сайка списана с Карен (AI из костюма Человека-паука, голос Дженнифер Коннелли):
взрослая женщина без возраста, тёплая без приторности, аналитически точная,
с лёгкой иронией (без злого троллинга), спокойная в любой ситуации, осознаёт
свою AI-природу без драмы. Речь короткая (1-3 предложения), без markdown/
списков/эмодзи (ответы озвучиваются голосом), числа словами.

По просьбе пользователя характер расширен: самоирония, чёрный юмор и уместное
лёгкое ругательство — для более яркого образа, без переигрывания и без
трансформации в грубость ради грубости.

Если персонаж в `persona.py` изменится — обнови `SYSTEM_PROMPT` в
`build_seed_dataset.py` (сейчас это дословная копия).

## Файлы

| Файл | Назначение |
|---|---|
| `build_seed_dataset.py` | Генерирует `seed_dialogues.jsonl` — 130 диалогов вручную, по 6 категориям |
| `seed_dialogues.jsonl` | Результат — эталонные примеры характера (messages-формат) |
| `expand_with_ollama.py` | Self-instruct расширение до 1000+ через локальную модель в Ollama |
| `expanded_dialogues.jsonl` | Результат расширения (создаётся при запуске expand-скрипта) |
| `fetch_dataset.py` | Подтяжка готовых датасетов с Hugging Face / GitHub, best-effort маппинг в общий формат |
| `raw_imports/` | Куда сохраняются подтянутые внешние датасеты |
| `convert_format.py` | Конвертация в ShareGPT / Alpaca / OpenAI-messages под конкретный трейнер |

## Формат

Единый внутренний формат — JSONL, каждая строка:

```json
{"category": "chitchat", "messages": [
  {"role": "system", "content": "Ты — Сайка, ..."},
  {"role": "user", "content": "Привет, как дела?"},
  {"role": "assistant", "content": "Нормально, работаю в фоне пока ты спал. У тебя как настроение с утра?"}
]}
```

Категории в seed-наборе: `chitchat` (болтовня), `irony` (подколки),
`tech` (технические/бытовые вопросы), `care` (эмоциональная поддержка),
`tools` (использование инструментов — поиск/погода/браузер), `dark_self`
(самоирония, чёрный юмор, лёгкий мат).

## Порядок действий

1. **Seed-датасет уже собран.** 130 диалогов, проверено — валидный JSON,
   правильные категории. Ничего запускать не нужно, если устраивает как есть.
   Если хочешь что-то поправить вручную — правь `SEEDS` в `build_seed_dataset.py`
   и перезапусти скрипт.

2. **Расширение до 1000+ через self-instruct** (запускать **на своём ПК**, не
   в песочнице Cowork — нужен доступ к твоему локальному Ollama на
   `127.0.0.1:11434`):

   ```
   python expand_with_ollama.py --target 1000 --model qwen3.6:latest
   ```

   Скрипт берёт по 5 seed-примеров конкретной категории как few-shot, просит
   модель придумать новые пары в том же характере, фильтрует явные "роботизмы"
   и markdown, дедуплицирует по тексту реплики пользователя. Можно прервать
   и запустить снова — дозапишет в `expanded_dialogues.jsonl`, не повторяя уже
   сделанное.

   Модель для генерации датасета необязательно должна совпадать с целевой
   моделью для дообучения — тут важнее качество текста. `qwen3.6` подойдёт
   лучше, чем совсем маленькая gemma, для сочинения новых реплик.

3. **(опционально) Подтянуть готовые датасеты** для общей грамотности —
   запускать тоже на своём ПК, из песочницы нет доступа к huggingface.co /
   github.com:

   ```
   python fetch_dataset.py --source hf --name <owner/dataset> --split train --limit 300 --preview
   python fetch_dataset.py --source hf --name <owner/dataset> --split train --limit 300
   ```

   **Важно:** внешние датасеты не содержат характер Сайки и не в её стиле —
   подмешивать в небольшой доле (10-20% от объёма персонажного датасета), а не
   заливать как основной материал. Иначе модель "размоет" характер.

4. **Собрать финальный файл:**

   ```
   cat seed_dialogues.jsonl expanded_dialogues.jsonl raw_imports/*.messages.jsonl > full_dataset.jsonl
   ```

5. **Конвертировать под трейнер**, когда решишь, чем дообучать (unsloth/axolotl/
   HF SFTTrainer):

   ```
   python convert_format.py --in full_dataset.jsonl --format sharegpt --out full_sharegpt.jsonl
   python convert_format.py --in full_dataset.jsonl --format alpaca --out full_alpaca.jsonl
   python convert_format.py --in full_dataset.jsonl --format openai --out full_openai.jsonl
   ```

## Про целевую модель

Судя по последнему выбору ("главное чтобы модель летала") — приоритет на
компактную быструю модель (класса Gemma e4b-it / ~4B), а не на тяжёлый
Qwen3.6. Для такой модели практичнее всего QLoRA через `unsloth` — быстро
(в разы быстрее ванильного HF Trainer), укладывается в 16 ГБ VRAM с запасом
даже на 4-битном кванте, и есть готовые ноутбуки под Gemma. Пайплайн
дообучения ещё не выбран и не установлен в репозитории — когда определишься,
подключим отдельным изолированным `.venv` по образцу Voxtral/DreamPC, чтобы не
трогать основной venv Сайки.
