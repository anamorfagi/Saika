## 1. Двенадцать пунктов владельца → что за ними в коде

### (1)(2) Визуал ломается на разных масштабах, кнопки наезжают
Атлас живёт не в `index.html`, а в отдельной странице `ui/hearing.html`
(2427 строк, three.js инлайном), которая грузится **в iframe**
(`index.html:15607-15617`).

Кнопки — **три независимых острова `position:absolute`**, ничего не знающих
друг о друге: `#coatbar` слева (`hearing.html:100`), `#srcmode` по центру
через `left:50%` (`hearing.html:82`), `#clrbtn`/`#snapbtn`/`#axbtn` справа
этажами `bottom:16/56/96px` (`hearing.html:114-122`). Медиазапросы есть
(`186-202`), но они меряют **ширину iframe**, а iframe — это `2fr` из
`2fr 1fr` (`index.html:13735`). На окне 1700px атлас получает ~1050px и
уходит в режим «<1240», хотя человек видит широкое окно. Плюс ширина
русских подписей нигде не считается — абсолютная раскладка гарантировать
непересечение не может в принципе.

**Лечение:** один flex-подвал вместо трёх островов + брейкпоинты по
`ResizeObserver` самого `#stage`, а не по вьюпорту.

### (3) Справа чат, которого не просили
Это `.ears-right` — колонка, собираемая в JS (`index.html:15680-15702`):
сверху «ЧТО ОНА СЛЫШИТ» (`15688-15697`, лента из `EARS_LOG`), под ней
«ТЕХНОЛОГИЯ / Акустическая топология» с захардкоженным «Полным циклом»
(`15665-15676` — обычный строковый литерал). Тумблера нет: блок живёт
ровно столько, сколько открыта панель.

### (4) Кривой запуск: раскрылось на всю ширину → уехало влево
Это **сделано намеренно** и рассинхронизировано:
`zpInner()` вешает `zi-full` → `.zi-grid{grid-template-columns:1fr 0fr}`
(`index.html:13653`), то есть правая колонка схлопнута в ноль, и снимает
его **по `setTimeout(…, 520)`** (`16126`); колонки едут обратно к `2fr 1fr`
плавным `transition .50s` (`13652`). А `src` у iframe ставится на **680 мс**
(`15616`) — то есть три.js начинает грузиться уже ПОСЛЕ того, как
раскладка доехала. Отсюда «раскрылось, мигнуло чёрным, съехало».

Хуже: 500 мс анимации `grid-template-columns` меняют ширину `#stage`
каждый кадр → каждый кадр `ResizeObserver → renderer.setSize()`. На одном
из кадров браузер отдаёт нулевую ширину, `camera.aspect = Infinity`
необратимо ломает матрицу — от этого в `hearing.html:754-767` стоит
костыль-заглушка на нулевые размеры.

**Лечение:** ставить `src` iframe ПЕРВЫМ, снимать `zi-full` по
`transitionend`, а не по таймеру; открывать сразу в конечной раскладке
(визуал + описание), без такта «во весь экран».

### (4б) Полный экран для визуализации
Не реализован; у iframe даже нет `allow="fullscreen"` (`index.html:15631`).
Механика «карта на всю панель» **уже написана** — тот самый класс
`zi-full`. Достаточно сделать его переключаемым по кнопке вместо
одноразового снятия таймером. Нативный fullscreen — вторым уровнем, через
`stage.requestFullscreen()` + правку `allow`.

### (5) Кнопки источника: система / сис+микро / микро / соцсети
Сейчас это **чисто клиентский фильтр** над потоком, который сервер и так
шлёт: `SRC_ACCEPT` в `hearing.html:1618-1620`. «система» и «соцсети»
функционально **идентичны** (`social: {sys:1}`). Кнопка шлёт наверх
`postMessage({saikaSrcMode})` (`1630`) — и **этого сообщения в
`index.html` не слушает никто**, ноль вхождений. То есть человек жмёт
«микро», а сервер продолжает слать `sys`, и карта просто перестаёт расти.

Твой порядок (микро → сис+микро → система → соцсети) требует, чтобы
кнопка **реально переключала канал на сервере**, а не фильтровала кадры
в браузере. Это правка сервера, не только вёрстки.

### (6)(10)(12) Современное распознавание, метки, многодорожечность
Проверено сегодня по первоисточникам:

- **GigaAM v3** — MIT, e2e_rnnt даёт пунктуацию и **пословные тайминги**,
  есть **экспорт в ONNX (fp16, onnxruntime-gpu)**. Потокового режима
  **нет**: `.transcribe` до 25 секунд, дальше `.transcribe_longform`.
  Значит realtime из него добывается только перечитыванием растущего окна —
  но перечитывание должно стоить **сотни миллисекунд, а не пять секунд**.
- **NVIDIA Streaming Sortformer 4spk v2.1** — 117M параметров, вход 16 кГц
  моно, выход **матрица T×4 вероятностей активности каждого из 4
  говорящих по кадрам 80 мс**, низколатентная конфигурация **1.04 с**,
  RTF 0.002–0.093. Лицензия NVIDIA Open Model. Требует NeMo; про Windows
  и ONNX в карточке ничего.

Вот это и есть ответ на пункты 10 и 12: **кто говорит — решает не разрез
фразы постфактум, а покадровая дорожка активности говорящих, идущая
параллельно звуку.** Два голоса разом перестают быть «crowd, который надо
разделить SepFormer'ом за 300 мс» и становятся двумя одновременно
активными строками матрицы.

### (7) Голос создателя
`voiceprint` умеет ручной enroll (`enroll_start/finish/file`) и золотую

### (8)(9)(11) Транскриб, метки звука, достройка по смыслу
Уже есть и работает: `misheard` (фонетический ключ + Левенштейн),

### Отдельно: черновик не работает на системном звуке — структурно
Ветка `if src == "sys"` в `_hear_worker` делает `continue` на

серых слов не будет никогда, сколько ни чини Vosk.

## 2. Целевая архитектура

Главный сдвиг: **разорвать один поток на два независимых контура.**

```
                    ┌─ БЫСТРЫЙ КОНТУР (цель < 300 мс) ──────────────┐
 звук 100мс ─ Ст.0 ─┤  streaming-диаризация (Sortformer, кадр 80мс)  │→ дорожки
                    │  streaming-черновик (Vosk / чанковый ONNX)     │→ слова
                    └───────────────────────────────────────────────┘
                    ┌─ ТОЧНЫЙ КОНТУР (сколько нужно, но без очереди) ┐
                    │  GigaAM ONNX fp16 по границам ДОРОЖКИ,         │
                    │  а не по паузе; пословные тайминги             │
                    │  → misheard → оконный rescore+router (Ст.5)    │
                    └───────────────────────────────────────────────┘
```

Что из этого следует по пунктам:

1. **Границу фразы задаёт смена говорящего, а не пауза.** Рампа soft-cut
   (`manager.py:229`, с 3.6-й секунды требуемая пауза съезжает с 600 до
   100 мс) существует только потому, что мы не знаем, кто говорит.
   Покадровая дорожка активности эту рампу отменяет — вместе с обрывами
   предложений на вдохе.
2. **`turns.split` уходит целиком.** Разрез по смене тембра постфактум —
   это самодельная диаризация, и она же главный расход GPU.
3. **SepFormer перестаёт быть обязательным.** Он нужен, только когда две
   дорожки активны и надо физически разделить сигнал под ASR; решение
   принимает диаризатор, а не эвристика `crowd`.
4. **Один эмбеддинг на сегмент, кэш по куску.** ECAPA остаётся для одной
   задачи — **узнать владельца** и привязать номер дорожки к имени
   человека. Не для кластеризации.
5. **`auto_meet` из одного центроида уходит.** Именно он даёт «Дорожки
   пересобраны: людей 1» и filler «Э-э» в списке голосов.
6. **Черновик перестаёт зависеть от канала.** Условие смотрит на VAD того
   канала, из которого пришёл кусок, а не на микрофонный.

## 3. Порядок работ (по отдаче, не по красоте)

**Э1. Разгон до реального времени.** Без этого остальное бессмысленно.
- кэш эмбеддинга на сегмент (снимает 2 из 4 прогонов GPU);
- GigaAM → ONNX fp16 (`model.to_onnx()`, onnxruntime-gpu);
- `turns.split` под флаг, по умолчанию выкл. на время замеров;
- цель: `stt_ms` < 800 мс на 8-секундном куске.
- **замер:** `replay eval_take.wav` до/после, `stt_ms` + «пролежал в очереди».

**Э2. Черновик на оба канала.** Мелко, чинит то, ради чего всё затевалось.
- условие черновика по VAD своего канала; sys-ветка получает черновик;
- `_live_polish` перечитывает растущий кусок ONNX-движком.

**Э3. Streaming-диаризация.** Sortformer в отдельном venv-воркере (как
Voxtral: свой процесс, HTTP на localhost — на Windows это единственный
надёжный способ утащить NeMo).
- выход: `speaker_id + вероятность` на каждые 80 мс;
- граница сегмента = смена доминирующей дорожки;
- две активные дорожки → два параллельных транскриба (пункт 12).

**Э4. Личности поверх дорожек.** ECAPA привязывает номер дорожки к имени;
печать владельца перепечатывается по паспорту (пункт 7).

**Э5. Ст.5 — оконный LLM-проход.** rescore + router одним вызовом:
чинит слова под фонетическим гардом и разносит спорные метки по логике
диалога (пункты 8, 11).

**Э6. Визуал.** Подвал одним flex-контейнером, брейкпоинты по `#stage`,
запуск сразу в конечной раскладке, переключаемый полный экран,
кнопки источника реально переключают канал на сервере (пункты 1–5).

## 4. Развилки, где нужен выбор владельца

1. **NeMo на Windows.** Sortformer без NeMo не запускается, про Windows в
   карточке модели молчок. Ставить отдельным venv-воркером — реально, но
   это ~несколько ГБ и вечер возни, и может не встать вообще. Альтернатива
   на время: оставить ECAPA, но заменить `auto_meet` онлайн-кластеризацией
   (леадер/DP-means) — хуже по качеству, зато без новых зависимостей.
2. **Лицензия.** GigaAM — MIT, вопросов нет. Sortformer — NVIDIA Open
   Model License; под платную версию это надо читать отдельно (см.
   saika-licenses).
3. **Визуал: чинить или переписать.** `hearing.html` — 2427 строк с
   three.js инлайном. Чинить подвал и тайминги — день. Переписывать
   визуализацию под покадровые дорожки — это уже другая картинка (не
   облако точек, а параллельные ленты активности во времени).
