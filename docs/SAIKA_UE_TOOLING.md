# Инструментарий UE-ветки: чем и как править проект

Дополнение к `SAIKA_UE_STATUS.md`. Про то, как вообще работать с проектом
через ассистента, и какие ограничения известны. Собрано 2026-08-05 по
результатам первого вечера — каждый пункт стоил времени.

## Три канала в редактор

**1. MCP (`unreal-mcp`, порт 8000).** Основной. Умеет: ассеты, акторы,
компоненты, материалы и их экземпляры, скелетные меши, текстуры, сцена,
блюпринты (обычные), Sequencer, Control Rig. Есть пакетный запуск через
`ProgrammaticToolset.execute_tool_script` — им надо пользоваться, когда
операций больше трёх, иначе уходит время на круговые рейсы.

**2. Питон редактора.** `Content/Python/init_unreal.py` поднимает «почтовый
ящик»: следит за `Saved/SaikaPy/run.py` и выполняет его при изменении.
Через него доступно то, чего нет в MCP. Результат удобно писать в
`Saved/SaikaPy/out.json` и читать снаружи.

**3. C++ модуль `Source/SaikaUE/`.** Логика реального времени: связь с
сервером, липсинк. Правится файлами, собирается извне.

## Что MCP НЕ умеет (проверено)

- **Создать `AnimBlueprint`.** Инструмент `BlueprintTools.create` отвечает
  окном «Невозможно создать схему на основе класса AnimBlueprint»: фабрике
  нужен целевой скелет, а параметра для него нет. Вызов при этом **зависает
  до таймаута**, пока окно ждёт нажатия OK, и весь редактор блокирован.
  Обход — питон: `unreal.AnimBlueprintFactory` + `target_skeleton`.
- **Создать уровень.** Есть только `load_level`. Обход — дублировать
  `/Engine/Maps/Templates/Template_Default` и вычистить.
- **Добавить компонент в блюпринт (SCS).** `ActorTools.add_component`
  работает по живому актору в сцене, но не по блюпринту.
- **Импортировать FBX с морфами.** У инструмента нет галочки; правится
  через дефолты класса `/Script/UnrealEd.Default__FbxSkeletalMeshImportData`
  перед вызовом импорта.
- **`AssetTools.write_file` не понимает `/Game/`.** Путь `/Game/Python/x.py`
  он резолвит как `c:\game\python\x.py` и отказывает. Передавать настоящий
  путь: `C:/AI/SaikaUE/Content/Python/x.py`. Разрешены только `Content/`,
  `Saved/` и `Content` включённых плагинов.

## Модальные окна блокируют всё

Любой инструмент MCP, который откроет модальное окно, повесит редактор
целиком: следующие вызовы уйдут в таймаут. Признак в логе — строка
`Dispatching toolset tool: '<имя>'` без пары. Лечится нажатием кнопки в
окне; предотвращается тем, чтобы не звать заведомо диалоговые операции.

## Сессия MCP умирает при перезапуске редактора

**Главная бытовая заноза.** При каждом старте редактора MCP заводит новую
сессию, а прослойка `mcp-remote` держит старую и получает:

```
LogModelContextProtocol: Error: Unknown session id '...' for 'tools/call';
client should reinitialize
```

Со стороны ассистента это выглядит как таймаут. Лечится вручную:
в приложении Claude → `Настройки → Developer` → сервер `unreal` выключить
и включить.

**Вывод: перезапусков редактора надо избегать.** Отсюда правило ниже.

## Цикл правок C++

Полная пересборка требует закрытого редактора — иначе UnrealBuildTool
пишет `Unable to build while Live Coding is active`. Причём
`CloseMainWindow()` редактор не закрывает, нужен `Stop-Process -Force`.

```
Build.bat SaikaUEEditor Win64 Development -Project="C:\AI\SaikaUE\SaikaUE.uproject" -WaitMutex
```

Первая сборка модуля — 62 секунды, инкрементальная — 13.

**Но по возможности пересборку не делать.** Для правок ТЕЛ функций
достаточно **Live Coding**: правим `.cpp`, в редакторе `Ctrl+Alt+F11`,
модуль перекомпилируется на лету. Редактор не перезапускается, сессия MCP
жива. Ограничение: так нельзя менять заголовки с `UPROPERTY`/`UFUNCTION`
и добавлять новые классы — для этого полная пересборка.

## Полезные мелочи

- `EditorAppToolset.CaptureAssetImage` рендерит превью ассета — быстрый
  способ увидеть результат, не гоняя скриншот всего редактора.
- `EditorToolset.LogsToolset` читает Output Log движка.
- Логи проекта: `C:\AI\SaikaUE\Saved\Logs\SaikaUE.log`. Свои сообщения
  модуля — под категорией `LogSaikaLink`.
- Проект запускать через `Launch_UE58.bat`: двойной клик по `.uproject`
  предлагает только 5.7, потому что лаунчер Epic не прописал `UE_5.8`
  в `LauncherInstalled.dat`.
