**Вечер 22.08, добивание по логам (слух заработал, голос — три причины подряд):**
- СЛУХ ПОЕХАЛ: gigaam распознаёт за 0.3–1.6 с. Последним барьером был `[WinError 2]` — пакет грузит звук ТОЛЬКО через внешний ffmpeg, которого в сборке нет. Теперь `_gigaam_no_ffmpeg()` подменяет `load_audio` во всех модулях пакета: читаем свой wav через soundfile, частоту правит torchaudio.
- ГОЛОС, причина 1: `Автопуск: озвучка выключена в настройках — не гружу`. Ступень разгрузки памяти писала `tts.engine=off` В КОНФИГ, то есть на все будущие запуски. Теперь она оставляет `tts.engine_was`, автопуск возвращает голос и говорит об этом вслух, а ручной выбор «Без озвучки» записку стирает (та же болезнь, что была с `tts.enabled`).
- ГОЛОС, причина 2: llama-server занимал 12.7 из 16.4 ГБ — окно раздувалось до 32768, потому что правило «беру большее» тянуло ключ ЧУЖОГО движка (`locallm_gguf` = T-lite). Расчёт вынесен в `_eff_ctx()`, при тяжёлом голосе окно ужимается до `llamacpp.n_ctx_voice_cap` (16384). **Важно:** `_sig()` теперь считает подпись по `_eff_ctx()`, иначе живой сервер со старым окном не перезапускался бы — правка выглядела применённой, а память не освобождалась.
- ГОЛОС, причина 3: `Cannot find a working triton installation` — на Windows Triton нет, а `enable_streaming_optimizations(use_compile=True)` без него роняет движок. Теперь `_triton_ok()` проверяет заранее, компиляция включается только если есть; при любой беде — повтор без неё, а если упал сам поток, `speak()` доигрывает непотоковым `generate_voice_clone`. Лучше медленнее, чем чужим голосом.

Мы не подменяем объекты, а **переписываем их нутро** (`__code__`, `__defaults__`, методы класса) — объект тот же, все ссылки разом видят новое. Так делает autoreload в IPython.
- Главный модуль перечитать целиком нельзя (верхний уровень поднимает сервер) — для него **хирургия по определениям**: сравниваем файл со снимком, исполняем только изменившиеся `def`/`class` прямо в его же globals. Декоратор маршрута отрабатывает сам, старый маршрут с тем же адресом снимается (иначе FastAPI зовёт первый по списку).
- ⚠️ **Снимок исходника снимается на СТАРТЕ** (`live.remember`, зовётся в `_code_watch`). Поймано стендом: к моменту правки файл на диске уже новый, и «как было» взять неоткуда — разница всегда пустая, применялось ноль. Снимка нет → применяем ВСЁ (безопасно).
- Не применяется только правка верхнего уровня самого `main.py` (новая константа/импорт) — и она **называется вслух** в чат и в лог, а не проглатывается.
- `_hot_restart()` выпотрошен в заглушку: обе его ветки (код 7 / «нажми ⟳») означали одно — живого обновления нет.
- Проверено на настоящем FastAPI: смена тела обработчика, смена помощника (видна по СТАРОЙ ссылке), **добавление нового маршрута на лету** (404 → 200), без дублей. `tests/test_live_reload.py` — 11 проверок.

## 6. Как устроено и чем работать
- Сервер: FastAPI, `anamorf/main.py` (~9k строк). UI — один файл `ui/index.html` (~15.6k строк / ~907 КБ). WS `/ws` с автопереподключением и самоперезагрузкой по `BOOT_ID`. Каталог `server/` переименован в `anamorf/`.
- `ROOT` vs `DATA_ROOT`: в сборке `ROOT = app/` (заменяется целиком при обновлении), `DATA_ROOT` — родитель. `resolve()` шлёт `data/`, `logs/`, `models/`, `voice/` в DATA_ROOT.
- `config.local.json` накладывается поверх `config.json` (LOCAL_KEYS: `llm.backend`, `llm.model`, `stt.engine`, `tts.engine`, …). **Живой процесс переписывает конфиг** — ручные правки только при закрытой проге. Сейчас там `stt.engine=gigaam`, `tts.engine=qwen3`, `llm.backend=llamacpp`, `llm.model=google/gemma-4-e4b`.
- `device_bash` (машина Anamorf): таймаут 45 с — **не запускать `find` по корню проекта**; `rm` запрещён — переносить в `_to_delete/`. Сеть недоступна.
- Облачный контейнер `bash`: сеть по allowlist (CDN Сбера — 403), Playwright есть: `require('/opt/node-tools/node_modules/playwright')`, `executablePath: '/opt/pw-browsers/chromium'`, стенд поднимать локальным http-стабом, скин задавать через `addInitScript` → `localStorage.saika_skin='graphite'`.
- Проверка синтаксиса: `node --check` по вырезанным `<script>`-блокам `ui/index.html` — **блок 26 это CSS и всегда «сломан»**, это ложное срабатывание, точно такое же на чистой копии.
- Мерить размер файла — только `wc -c` (байты), не `len(s)`: на этом уже был ложный «файл усох на 174 КБ».
- Если приложение открылось пустым окном — первым делом подозревать отравленный `sessionStorage` в уже открытой вкладке, а не код: один раз это стоило зря удалённого восстановления экрана.
