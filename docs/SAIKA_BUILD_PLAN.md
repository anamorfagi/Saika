## 1. Что есть на самом деле

Сайка сейчас — не приложение, а **рабочий стенд разработчика**, который умеет очень много.
Граница «продукт / инструменты автора» не проведена нигде: доска разработки, git-кнопка,
чтение собственного исходника, вкладка дообучения LoRA и личные пути автора живут в том же
процессе, что и диалог с пользователем.

Что мешает назвать это приложением:

| | как есть |
|---|---|
| Версия | нет ни `VERSION`, ни `__version__`, ни тегов, ни changelog. Единственный идентификатор — хэш коммита |
| Сборка | `tools/make_package.py` = zip всей папки вместе с `.venv` и `models/` → **100+ ГБ** |
| Установка | `setup/first_run.py`, 16 шагов, ~5 ГБ pip-трафика, `git clone` двух репозиториев, whl с GitHub, `winget` для Python/ffmpeg/Ollama. Часы, и результат не воспроизводим |
| Обновление | `git pull --ff-only` в клоне рабочего репозитория. Нужен git в PATH и настроенные креды |
| Откат | отсутствует. Плохой коммит в `dev` = сломанные клиенты |
| CI | `.github/workflows` нет. `tests/` (13 файлов) никто не гоняет |
| Секреты | `config.json` **лежит в git** и содержит `server.token`, `owner.name = "Anamorf"`, `messengers.telegram.token`, `messengers.owner_ids`, `tts.voice_ref_text` (транскрипт голоса автора) |
| Точка входа | `server/main.py` — 9 603 строки, ~160 HTTP-ручек, `run_dialog` 2 046 строк, `ws_endpoint` 2 212 строк |
| Обработка ошибок | 276 мест `except Exception: pass` |

Сильные стороны, которые надо сохранить и на которых можно строить продукт:
самопочинка (`doctor.py` → `ai_doctor.py` → `self_heal.py`), классификатор поломок
`diagnostics.py`, ступени разгрузки `triage.py`, `send_gate.py` (отправка только по
подтверждению), `trust.py`, паспорт моделей, переносимый дизайн (венвы и модели внутри
папки проекта). Это редкие и дорогие вещи, их в продукте не хватает почти всем.

### Про «толстый дистрибутив»

Ты выбрал «всё внутри». Честно: `models/` весит **103 ГБ** (LLaDA 8B ×2, Huihui-Qwen3.5 9B,
LLaDA-MoE, T-one, Voxtral, Qwen3-TTS, GGUF-и). Это не раздаётся.

Предлагаю читать «толстый» так: **один рабочий комплект под целевое железо**, а не всё,
что когда-либо качалось:

| компонент | что берём | вес |
|---|---|---|
| LLM | один GGUF 4–8B, Q4_K_M | 3–5 ГБ |
| Слух | gigaam v3 (+ vosk-small как черновик) | ~1.3 ГБ |
| Голос | silero + один пресет Qwen3-TTS | 2–3 ГБ |
| Зрение/OCR | Windows.Media.Ocr (в системе) | 0 |
| runtime | Python 3.12 + torch cu130 + пакеты | 5–7 ГБ |
| **итого установщик** | | **12–16 ГБ** |

Всё остальное (Voxtral, DreamPC, CLAP, PANNs, вторая LLM) — докачка по кнопке из самого
приложения. Тогда «толстый» билд работает офлайн сразу после установки и при этом
физически раздаётся.

## 3. Блокеры компиляции и схема сборки

### Что сломается при заморозке в exe

| проблема | где | что делать |
|---|---|---|
| **`pip install` в рантайме** | `browser_hands.py:109`, `desk_avatar.py:164`, `hotkeys.py:185` — вызывают `sys.executable -m pip install`. В замороженном exe `sys.executable` — сам exe, pip отсутствует | вырезать; заменить на «Установить компонент» через отдельный установщик |
| `comtypes` пишет COM-обёртки в кэш | `pc_control.py`, `ui_hands.py` | задать `COMTYPES_CACHE_DIR` в writable-папку рядом с данными, прогреть кэш при сборке |
| чтение своих исходников | `self_read.py` | убрать из клиента |
| `fitz` (PyMuPDF) | `pdf_hands.py` — **нет в `requirements.txt`** | добавить или убрать модуль |
| два имени одного пакета | `browser_hands.py` импортирует и `ddgs`, и `duckduckgo_search` | оставить один |
| `numpy` | `requirements.txt` пинит `1.26.4`, а шаг `numpy_fix2` в `first_run.py` ставит `>=2,<2.5` | развести окончательно, иначе сборка непредсказуема |
| `winsdk==1.0.0b10` | `ocr.py`, бета WinRT-проекция | проверить под заморозкой, держать rapidocr как запасной |
| `os.add_dll_directory` для torch/cublas/nvrtc | `config.py` | пути в замороженном билде другие — переписать под раскладку runtime |
| `requirements.lock.txt` не используется **ни одним** скриптом | — | сделать его единственным источником правды при сборке |

### Раскладка билда

**Не морозить всё в один exe.** torch + CUDA + comtypes + pywinauto в PyInstaller-onefile —
это гарантированные многодневные раскопки и антивирусные ложные срабатывания.
Проверенная схема для проектов такого класса (ComfyUI portable, A1111):

```
Saika\
  Saika.exe          ← тонкий лаунчер (~1–2 МБ): проверить обновление,
                       починить пути, запустить сервер, открыть окно pywebview
  runtime\           ← Python 3.12 embeddable + site-packages (нынешний .venv)
  app\               ← код Сайки: server\ ui\ workers\ setup\  ← ЭТО ОБНОВЛЯЕТСЯ
  models\            ← модели (не трогаются обновлением)
  data\              ← память, профили голоса, настройки пользователя
  config.user.json   ← настройки пользователя (не трогаются никогда)
  VERSION            ← 0.9.4
```

Что это даёт:

- обновление = замена папки `app\` — **10–30 МБ вместо 12 ГБ**;
- `runtime\` версионируется отдельно и меняется редко (только когда меняются зависимости);
- модели и данные пользователя физически вне зоны обновления — их невозможно затереть;
- окно `pywebview` берёт готовый `ui/index.html` — переписывать интерфейс под Qt не нужно.

## 4. Система обновлений: твой билд и клиентский

### Два режима одного кода

| | dev (у тебя) | client (у людей) |
|---|---|---|
| откуда код | git-клон, ветка `dev` | папка `app\` из релиза |
| обновление | git-панель, как сейчас | апдейтер по каналу |
| доска разработки, git-кнопка, dataset_hub | есть | вырезаны при сборке |
| `SAIKA_DEV` | `1` | не задана |
| «Лаборатория» | открыта | за флагом |

Переключатель один: переменная `SAIKA_DEV` + флаг `build.channel` в манифесте.
Никаких двух веток кода — один репозиторий, разные профили сборки.

### Каналы

`stable` → `beta` → `dev`. Клиент по умолчанию на `stable` и может переключиться на `beta`
в настройках. Ты живёшь на `dev` из git.

### Поток релиза

```
ты: git tag v0.9.5 && git push --tags
     │
GitHub Actions:
     ├ pytest tests/ + smoke-import всех модулей server/
     ├ собрать app-0.9.5.zip (только продуктовые файлы, без dev-инструментов)
     ├ посчитать sha256, собрать manifest.json, подписать его
     └ опубликовать GitHub Release с тегом v0.9.5
     │
клиент (раз в сутки и по кнопке):
     ├ GET api.github.com/repos/anamorfagi/Saika/releases
     ├ выбрать свежайший релиз своего канала
     ├ сверить runtime_min: если нужен новый runtime — качать и его
     ├ скачать app-0.9.5.zip, проверить sha256 и подпись
     ├ распаковать в app.new\
     └ при следующем старте: app\ → app.prev\, app.new\ → app\
        сервер не поднялся за 60 с → откат из app.prev\ и сообщение
```

`manifest.json`:

```json
{
  "version": "0.9.5",
  "channel": "stable",
  "published": "2026-08-25T10:00:00Z",
  "app":     {"url": "...", "sha256": "...", "size": 24118000},
  "runtime_min": "3.12-cu130-r4",
  "runtime":  {"url": "...", "sha256": "..."},
  "migrations": ["0.9.4->0.9.5"],
  "notes": "Что изменилось — показывается пользователю",
  "signature": "..."
}
```

Готовый образец такого клиента **уже есть в проекте**: `setup/install_llamacpp.py` ходит в
`api.github.com/repos/ggml-org/llama.cpp/releases`, выбирает asset по тегу и версии CUDA,
качает zip, распаковывает и пишет `VERSION.txt`. Тот же паттерн применяем к самой Сайке.

### Конфиг: развести раз и навсегда

Сейчас `config.json` лежит в git, программа его сама переписывает при каждом `CFG.set()`,
и из-за этого родился костыль `AUTO_STASH = ("config.json", "DEVBOARD.md", "devboard.json")`
в `git_sync.py`. Разделение «общее/машинное» держится на белом списке `LOCAL_KEYS` из
12 путей — всё, что туда не попало (порт, токен, `owner`, `memory.*`, `llamacpp.n_ctx`),
затирается при первом же обновлении.

Новая схема:

- `app\config.default.json` — часть пакета, перезаписывается обновлением, **программа в него не пишет**;
- `config.user.json` — рядом с данными, только пользовательские правки, обновление его не трогает;
- `secrets.json` — как сейчас, вне пакета;
- значение = default ← user ← secrets.

`LOCAL_KEYS` после этого не нужен, `AUTO_STASH` не нужен, конфликты при обновлении
исчезают как класс.

### Что сделать до первого клиента

1. Выпустить токен `server.token` заново и убрать его из git — он лежит в открытом виде
   в истории репозитория. Туда же: перевыпустить токен Telegram-бота.
2. Убрать `config.json` из git, добавить `config.default.json` без личных данных.
3. `git gc` — в `.git` 724 мусорных объекта на 16 МБ от оборванных операций.

## 5. Интерфейс

Живой макет — отдельным файлом (`saika_ui.html`), открывается в браузере.
Кнопка ◐ справа вверху переключает тёмную и светлую тему.

### Стиль «Graphite»

Монохром, ни одного цветного акцента. Статус читается **контуром и яркостью**, не цветом.

- **Глубина слоями.** Тень = рассеянная + контактная + внутренний блик сверху.
  Пять уровней: `--s0` подложка → `--s1` плитка → `--s2` наведение → `--s3` активное →
  `--press` вдавлено. В светлой теме — мягкий рельеф, как на твоих референсах:
  тёмная тень снизу-справа, светлая сверху-слева.
- **Подъём при наведении.** Плитка поднимается на 3 px, светлеет на один уровень,
  тень растёт. 190 мс, `cubic-bezier(.2,.85,.25,1)`.
- **Контурная подсветка процессов сохранена**, но перерисована:
  `st-ready` — тонкий внутренний контур; `st-load` — бегущий по кругу сегмент
  (conic-gradient + mask); `st-work` — дышащая рамка; `st-err` — контур ошибки.
  Заливка при этом не меняется никогда — глаз ловит движение контура, а плитка спокойна.
- **Шрифт.** Inter Variable, начертания 200–500, плотный трекинг у заголовков,
  `tabular-nums` у чисел. Один файл `.woff2` кладётся в `ui/fonts/` и подключается
  через `@font-face` — интерфейс остаётся полностью офлайн, как сейчас.

### Центральный элемент — кольцо

Круг с надписью **ANAMORF** по центру, вокруг — радиальные полосы. Секторы кольца:
ЦП, ОЗУ, VRAM, GPU и голос. Первые четыре — то, что раньше жило столбиками в левой
колонке `#sysbar`; пятый сектор — звуковая волна с микрофона. Внутри две медленно
вращающиеся дуги — пульс системы. Есть большая версия (вид «Пульт») и компактная,
которая стоит в колонке рядом с чатом.

### Пересобранная раскладка

Сейчас: 266 идентификаторов, 21 панель, 15 разных типов всплывающих меню и шторок,
у каждой свой набор CSS-классов (`.pop`, `.ss-card`, `.ph-card`, `.sk-card`, `.dp-card`,
`.tr-drawer`…). Найти что-либо можно только зная, где оно лежит.

Новая структура:

- **Левый рельс (76 px)** — режимы: Пульт · Чат · Карта · Стиль · Голос · Образ · Система,
  внизу отдельно Настройки. Активный помечен полоской слева и подъёмом плитки.
- **Шапка** — имя, четыре индикатора состояния (мозги / слух / голос / глаза) как чипы
  с живой точкой, справа версия и канал обновлений, тема, язык, новый диалог.
- **Центр** — рабочая область режима.
- **Правая колонка** — контекст: состояние, нагрузка, доверие, «где я работаю». Схлопывается.
- **Нижний док** — композер: слушать, микрофон, поле, чип модели, вложение, отправить.
- **Все нынешние поповеры и шторки — в один тип правой выезжающей панели.**
  Один класс вместо пятнадцати.

### Дорожная карта вместо канбана

Пять колонок доски (В работе / Баги / В планах / Идеи / Готово) превращаются в
горизонтальную ленту этапов с ветвлениями. Прокрутка колесом или стрелками ‹ ›.
Кружок = этап: номер, название, дата, счётчик работ. Нажатие открывает отчёт справа —
что делали на этапе и чем кончилось. Там, где логика расходилась, лента ветвится на
параллельные дорожки и снова сходится: например после «Беймакса» работа разошлась на
слух, скорость и аватар, а сошлась на «Своих глазах и руках».

Данные взяты из твоего `devboard.json` — 13 этапов, от «Первого голоса» 16 июля до
«Сайки как игры» на горизонте. Впереди идущие этапы нарисованы пунктиром.

**Эта карта — только в твоей версии.** В клиентском билде вкладка «Карта» вырезается
вместе с `devboard.py`.

**Этап 2 — версия и профили сборки.**
`VERSION`, `/api/version`, флаг `SAIKA_DEV`, список файлов продуктового пакета,
разделение `config.default.json` / `config.user.json`.

**Этап 3 — раскладка билда.**
`runtime\` из embeddable Python по `requirements.lock.txt`, `app\`, тонкий `Saika.exe`,
окно pywebview, `COMTYPES_CACHE_DIR`, проверка запуска на чистой Windows без Python.

**Этап 4 — обновления.**
`updater.py` в клиенте, `manifest.json`, GitHub Actions на тег, атомарная замена `app\`
и откат на `app.prev\`, экран «что нового».

**Этап 5 — интерфейс.**
Токены стиля и компоненты, кольцо, пересборка раскладки, единая правая панель вместо
пятнадцати шторок, дорожная карта.

**Этап 6 — тесты и распил.**
CI на push, затем `server/api/` → `server/dialog/` → `server/ws/` по плану из
`ARCHITECTURE.md`, замена `except Exception: pass` на логирование.

Этапы 1–4 — это то, без чего клиентского билда не существует. 5 и 6 можно вести
параллельно после третьего.
