### Подробные отчёты разведок — в памяти проекта; здесь только решения.

## Что должно получиться (словами владельца)

- транскриб, максимально близкий к 100%, на ru / en / es / zh / ja / uk;
- мгновенно «чей это голос» → текст сразу в нужную дорожку;
- один человек = один голос, а не «несколько облачков»;
- слова с неправильным произношением подсвечены, рядом — как надо;
  орфография, диалекты, подсказки — анимированно, над словом или сбоку;
- быстрее реального времени и не жрёт машину;
- гарантированно узнаёт владельца и людей из окружения.

### Слой 1б — КТО ГОВОРИТ: логика разговора (владелец, 31.08)

**Три сценария — три разных ответа.** Не решать самое тяжёлое там, где
хватает номера канала.

| сценарий | чем решается | акустика нужна для |
|---|---|---|
| владелец стримит и говорит поверх ролика | `src=mic` — владелец, `src=sys` — ролик. Два физически разных потока. Не смешивать в один VAD, GLUE не клеит через канал | ничего (только узнать владельца) |
| Discord с компанией | бот получает **отдельный поток на каждого участника** с именем аккаунта — дорожки заданы транспортом (так у Soul-of-Waifu) | привязать аккаунт к знакомому голосу; заметить двоих на одном аккаунте |
| чужой ролик / несколько людей на один микрофон | полная машинерия ниже | всё |

**Решение — сумма свидетелей**, а не одна проверка:

```
оценка(k) = w1·cos(отпечаток, голос k)          — ReDimNet2 (чужие ~0.2, свои ≥0.45)
          + w2·P(k следующий | история очереди)  — структура разговора
          + w3·P(k | канал)                       — mic / sys / аккаунт
          + w4·P(k | текст)                       — имена, вопрос/ответ
решение = argmax; отрыв от второго < порога → «?» и в мозги (Ступень 5)
```

**Структура разговора как вероятности (не правила):**
- после A с наибольшей вероятностью говорит тот, кто был ПЕРЕД A (ABAB);
  в группе слабее, но выше случайного;
- пауза < ~400мс без наложения — тот же человек продолжает;
- вопрос (интонация вверх, вопросительное слово, «?» пунктуации) → смена
  говорящего почти всегда;
- короткие «ага/угу», смех — СЛУШАЮЩИЙ, не текущий говорящий;
- обращение по имени «Оля, подскажи…» → следующим говорит Оля, **и это
  привязывает кластер к имени** — главный источник имён для «Голос N».

**Перебивание:** наложение началось при говорящем A → новый голос ≠ A.
A замолчал → B перехватил, обрывок A остаётся в дорожке A с пометкой
«прервано». A продолжил → две дорожки параллельно. Кто остался после
наложения — косинус хвоста к A и к B. SepFormer гонять **только на участке
наложения** (сейчас режет весь сегмент: 5.2с на 3.3с звука).

**Задним числом:** решение в момент t пересматривается через несколько
секунд, когда контекст догнал — LLM-роутер переподписывает пузырь через
уже существующий `stt_regroup`/`pid`.

Честная оценка долей: акустика ~80%, структура разговора ~10–15% спорных,
последние проценты вживую не берутся — только задним числом.

### Слой 1в — вечеринка, перебивания, дуплекс: алгоритмы
Разведка 31.08 по первоисточникам (Cherry 1953; Mesgarani & Chang, Nature
2012; Johnsrude 2013; Sacks/Schegloff/Jefferson; Stivers PNAS 2009; Ward &
Tsukahara 2000; доки OpenAI Realtime; Moshi arXiv:2410.00037).

**Что говорит наука, в трёх строках.** Мозг на вечеринке не «чистит шум» —
он ведёт ЛУЧ ВНИМАНИЯ: кора буквально воспроизводит спектрограмму только
отслеживаемого голоса. Знакомый голос выделяется измеримо легче — даже без
осознанного узнавания. Люди отвечают через ~200 мс — то есть НЕ ждут
тишины, а ПРЕДСКАЗЫВАЮТ конец чужой реплики.

#### Алгоритм 1 — двухъярусная гипотеза «чей звук» (идея владельца: топология)
Атлас считает F0/центроид на каждый кадр — мгновенно. Отпечаток требует
~1с звука. Значит два яруса:
```
кадр 10мс:  топология даёт F0, яркость, полосу
            prior[k] ∝ близость(F0, полоса голоса k) · P_очереди(k)
            → мгновенная ГИПОТЕЗА (красим звук на карте, НЕ пишем в ленту)
кусок ≥1с:  ReDimNet2 → cos к голосам
            posterior[k] ∝ w1·cos + w2·prior[k] + w3·канал + w4·лексика
            → метка в ленту; расхождение с гипотезой -> гипотезной полосе
              снижаем вес (полосы у людей пересекаются, топология — только
              подсказка, никогда не приговор; урок pitch_groups)
```

#### Алгоритм 2 — луч внимания на владельца (cocktail party по-нашему)
Честный вывод разведки: открытого потокового TSE (выделение целевого
голоса из смеси по эталону) с весами под Windows/16кГц НЕТ. VoiceFilter-
Lite (2.2МБ, −27.7% WER на наложениях) — без весов; SpeakerBeam-SS (7.9M,
кадр 20мс, RTF 0.36 CPU) — без кода; USEF-TSE — CC BY-NC. Поэтому:
```
сейчас (без обучения): ГЕЙТ ПО ГОВОРЯЩЕМУ, а не фильтр звука
  на каждый VAD-сегмент: verify(эталон владельца) за 20мс (ReDimNet2)
  совпало → сегмент получает флаг owner=true:
    · приоритетная очередь STT (его куски распознаются ПЕРВЫМИ, мимо lag-дропа)
    · TTS мгновенно приглушается (duck), Сайка «поворачивается» слушать
    · терпение конца реплики ↑ (см. Алгоритм 3: дослушивает, не режет)
    · наложение поверх владельца → SepFormer ТОЛЬКО на участке наложения,
      дорожка владельца — главная, чужая — параллельной строкой
потом (обучение, этап 0.2.3): каузальный TSE ~8M в стиле SpeakerBeam-SS,
  кондиционированный НАШИМ 192-d эмбеддингом (чужие модели ждут свой
  d-vector — подсунуть нельзя, дообучение обязательно; база — ESPnet enh_tse)
```

#### Алгоритм 3 — конец мысли вместо секундомера (лечит «обрывы предложений»)
Замена рампы soft-cut (сейчас: после 3.6с речи паузы в 100мс хватает для
ножа — отсюда обрывы на вдохе). Три свидетеля, решение за ~200мс:
```
пауза обнаружена (Silero):
  P_конца = w1·SmartTurn(последние 8с звука)      # просодия: 8МБ, 12мс CPU, ru
          + w2·LiveKit-EOU(последние реплики)      # законченность фразы по тексту, ru
          + w3·длина паузы / базовая
  P_конца > верхний порог → фраза закрыта, отдаём в диалог
  P_конца < нижний порог  → ЖДЁМ ДАЛЬШЕ (человек вдохнул посреди мысли)
  между порогами → закрыть для транскриба, но GLUE склеит со следующей
для владельца: пороги терпеливее (eagerness=low, как у OpenAI semantic_vad)
для чужих из ролика: eagerness=high — там дослушивать некого
```

#### Алгоритм 4 — перебивание (таксономия CA → действия)
```
наложение началось при говорящем A:
  событие < 1с, без семантики («ага», «угу», смех) → BACKCHANNEL:
      не смена говорящего; в ленту как мини-реплику слушателя; A продолжает
  событие на предсказуемом хвосте A (P_конца уже высокая) → TERMINAL OVERLAP:
      не перебивание, просто ранний вход; обычная смена
  событие длинное, A замолчал → ПЕРЕХВАТ:
      сегмент A закрывается с пометкой «прервано», B — новая реплика
  событие длинное, A продолжает → ПАРАЛЛЕЛЬ:
      два транскриба, SepFormer на участке наложения
если новый голос = ВЛАДЕЛЕЦ (правило владельца):
  моментально: duck TTS → верификация 20мс → если Сайка говорила,
  ОНА — прерванная сторона: её ответ усекается ДО ФАКТИЧЕСКИ
  ПРОИЗНЕСЁННОГО (паттерн truncate из OpenAI Realtime — иначе она
  «помнит», что сказала то, чего не договорила), контекст дополняется
  репликой владельца, ответ достраивается от места обрыва
```

#### Алгоритм 5 — поддакивание (и почему по умолчанию НЕ звуком)
Наука: слот для «ага» открывается после ~110мс НИЗКОГО F0 у говорящего +
финальная интонация + пауза (Ward 2000; Gravano & Hirschberg 2009: чем
больше сигналов разом, тем вероятнее). Датчики уже есть (FCPE + VAD).
```
сигнал_поддакнуть = низкий F0 ≥110мс + IPU-граница + пауза 200-500мс
                    + Сайка НЕ говорит + говорил владелец
реакция (ручка assistant.backchannel):
  "visual" (по умолчанию): аватар кивает / уши / огонёк слушания — весь
      эффект присутствия без риска влезть в запись или задолбать
  "voice": тихое «мм», «ага» — редко, не чаще 1 раза в N секунд,
      никогда во время чужой речи
  "off"
```
Владелец сам сомневается, хочет ли слышать «ага» («вроде интересно, но
блин») — поэтому звук отдельной ручкой, дефолт визуальный.

**Полные дуплекс-модели** (Moshi 7B/24ГБ, Freeze-Omni 7B) в бюджет 3-4ГБ
не влезают и русского не знают — берём их ПАТТЕРНЫ (два независимых
потока, truncate, eagerness), не веса.

**Новые компоненты слоя:** Smart Turn v3 (pipecat) — 8МБ int8, 12мс CPU,
23 языка включая русский, датасет и код обучения открыты; LiveKit
turn-detector — ~0.1B ONNX int8 CPU, 14 языков включая русский, лицензия
LiveKit Model License (НЕ OSI — перед платной версией перечитать).

### Слой 3 — МОЗГИ (текст → правильный текст)
Оконный LLM-проход: rescore + router одним вызовом на окно последних
сегментов. Чинит спутанные слова под фонетическим гардом (правка обязана
ЗВУЧАТЬ похоже), разносит спорные метки говорящих по логике диалога,
достраивает недослышанное по контексту. Уже есть `rescore.fix_async` — он
однострочный; расширяем до окна. Цена — уже загруженные мозги, троттлится.

### Слой 4 — ПРОИЗНОШЕНИЕ (Duolingo и лучше)
Схема у всех открытых CAPT-систем одна и та же, но никто не делает её
потоковой и мультиязычной:

```
текст ASR ──G2P──▶ ожидаемые фонемы ─┐
                                      ├─▶ выравнивание ─▶ GOP на слово ─▶ подсветка + подсказка
звук ──фонемный распознаватель──▶ фактические фонемы ─┘
```

| звено | чем | языки | лицензия |
|---|---|---|---|
| фактические фонемы | **ZIPA-CR-NS-large ONNX int8** (ACL 2025): IPA, 88 «своих» языков включая все шесть; PFER 2.7 против 11.9 у wav2vec2-espeak и 22.3 у Allosaurus | все 6 | код MIT |
| ожидаемые фонемы | **CharsiuG2P** (100 языков, тот же IPA-алфавит, что у разметки ZIPA) + **g2pM** для zh-многозначности (97.3% против 86% у pypinyin) + **pyopenjtalk** для ja (моры + акцентные ядра) + **lang-uk** для uk (WER 1.23%) + **russian_g2p** для ru-ударений + **g2p_en** | все 6 | MIT / Apache / BSD — без GPL |
| оценка слова | **segmentation-free GOP** прямо из CTC-логитов ZIPA (IEEE TASLPRO 2026) — без forced alignment и без Kaldi; границы слова от ASR | все 6 | код открыт |
| тон / ударение | FCPE → контур F0; zh: тон по слогу против g2pM; en/ru/uk: ударение по гласным; ja: контур против акцентного паттерна pyopenjtalk | — | MIT |
| объяснение | мозги: «ты сказал /ɕ/ вместо /ʃ/, попробуй…» на языке пользователя — LLM генерирует ТЕКСТ поверх фонемных фактов, а не оценивает на слух (Speech-LLM «на слух» даёт PCC 0.2 — бесполезно) | все | — |

Отвергнуто: espeak-ng/phonemizer (GPL — в платный продукт нельзя

## Честные дыры — говорю заранее

1. **100% не бывает.** Реальная цель: ru WER ≤ 5% (GigaAM), en ≤ 6%
   (Whisper turbo), остальные ≤ 8–10%; и «один человек = один голос» на
   ролике Snailkick. Всё выше этого — уже мозги (слой 3), не акустика.
2. **Произношение на русском/украинском некому проверить**: единственный
   открытый датасет с человеческой оценкой (speechocean762) — английский,
   говорящие-китайцы, чтение. На остальных языках порог GOP калибруется
   ушами. ZIPA сам ошибается на акцентной речи (Latino/Asian группы дают
   худший PER) — часть подсветок будет ложной, нужен порог «не оценивать
   при низком SNR / перекрытии».
3. **Китайские тоны и японский питч-акцент** — только эвристики по F0
   против ожидаемого паттерна; готовой открытой модели уровня ELSA нет.
4. **Украинский — тонкий**: один движок (Parakeet), один G2P (lang-uk),

5. **Потоковый транскриб на все языки** — либо Voxtral Q4 с незамеренным
   WER, либо перечитывание растущего окна буферным движком (наш
   `_live_polish`). Второе честнее, и оно уже работает при RTF 0.37.
