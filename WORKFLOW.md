# Как человек доходит от задачи до результата
### и почему Сайка спотыкалась именно там, где человек не спотыкается

Дата: 2026-08-13. Повод — вопрос владельца: «чем обычно пользуется человек
за компом, какие действия он выполняет, чтобы пройти от задачи к её
выполнению? нам нужно описать логику и отработать её во всех этих
действиях».

---

## 1. Универсальный цикл

Любая задача за компьютером — от «включи музыку» до «собери отчёт» —
раскладывается на один и тот же цикл. Человек проходит его целиком, но
половину шагов не замечает, потому что они бесплатные: посмотреть на экран
стоит ему ноль усилий.

```
1. ЦЕЛЬ        что должно стать правдой в конце
2. МЕСТО       где это делается: программа / окно / поле / сайт
3. ПОПАСТЬ     открыть или переключиться; внутри — дойти до нужного места
4. УБЕДИТЬСЯ   глянуть: я там? оно готово принять ввод?
5. ДЕЙСТВИЕ    набрать / кликнуть / нажать / прокрутить / перетащить
6. ПОДТВЕРДИТЬ Enter, кнопка, «Сохранить» — без этого ничего не произошло
7. ПРОВЕРИТЬ   стало ли то, что хотел
8. ИНАЧЕ       понять причину и пойти ДРУГИМ путём, а не повторять тот же
9. ДОКЛАД      сказать человеку правду о результате
```

**Главное наблюдение.** Шаги 3, 5, 6 — это «руки», и они у Сайки давно
есть: `app_launch`, `window_focus`, `keyboard_type`, `key_press`,
`screen_click`, `screen_scroll`. А шаги **2, 4, 7, 8** — это «глаза и
голова», и именно их не хватало. Отсюда весь наблюдаемый брак: она
отвечала «Закрываю Blender» и не вызывала ничего, потому что у неё не было
процедуры, которая обязывает *сначала посмотреть, потом сделать, потом
проверить*. Модель без процедуры пересказывает намерение — это не глупость
модели, это отсутствие регламента.

Второе наблюдение: **шаг 6 люди тоже не замечают**. «Напиши маме привет» для
человека заканчивается нажатием Enter. Модель же считает задачу выполненной
после набора текста — и сообщение остаётся несоставленным в поле ввода.
Подтверждение должно быть отдельным явным шагом, иначе оно теряется.

## 2. Инвентарь: что человек реально делает руками

### А. Между программами
запустить · переключиться (Alt+Tab) · свернуть · развернуть · закрыть ·
раскидать по половинам экрана (Win+←/→) · на второй монитор

### Б. Внутри программы
вкладки (Ctrl+T / Ctrl+W / Ctrl+Tab) · меню (Alt, F10) · диалог (Enter /
Esc) · поиск внутри (Ctrl+F) · настройки · полный экран (F11)

### В. Текст
поставить курсор в поле · набрать · выделить (Ctrl+A, Shift+стрелки) ·
копировать / вставить / вырезать · отменить (Ctrl+Z) · сохранить (Ctrl+S) ·
**отправить (Enter)**

### Г. Файлы
найти · открыть · переименовать (F2) · переместить · удалить · создать
папку · распаковать · показать в проводнике

### Д. Браузер
адрес (Ctrl+L) · поиск · выбрать нужный результат из выдачи · прокрутить до
нужного места · найти на странице (Ctrl+F) · назад (Alt+←) · скачать ·
закрыть рекламу

### Е. Медиа и система
громкость · пауза / плей · следующий трек · полный экран · яркость

### Ж. Игра
вывести окно в фокус · WASD и мышь · пауза (Esc) · выйти из игры не убив её

## 3. Цикл, разложенный по видам задач

Ниже — то, что должно происходить у Сайки в голове по каждому виду. Это
регламент, а не реплики: что говорить, она решает сама своим характером.

### Программы
```
МЕСТО      apps_list / window_list — оно уже открыто или надо запускать?
ПОПАСТЬ    открыто -> window_focus; закрыто -> app_launch
УБЕДИТЬСЯ  window_list: моё окно впереди?
ПРОВЕРИТЬ  окно есть и в фокусе. Нет — сказать честно, не рапортовать
ИНАЧЕ      имя не нашлось -> apps_list и переспросить; окно от админа ->
           сказать прямо, что Windows не даёт (это не отговорка, это факт)
```

### Текст в программу или на сайт
```
МЕСТО      куда именно: какое окно, какое поле
ПОПАСТЬ    window_focus нужной программы
УБЕДИТЬСЯ  screen_read — есть ли поле ввода и как оно называется
ДЕЙСТВИЕ   type_into(поле, текст) — точнее, чем keyboard_type вслепую
ПОДТВЕРДИТЬ Enter (key_press) — БЕЗ ЭТОГО НИЧЕГО НЕ ОТПРАВЛЕНО
ПРОВЕРИТЬ  screen_read ещё раз: текст ушёл, поле опустело?
ИНАЧЕ      поля нет -> клик по области ввода, потом keyboard_type
```

### Файлы
```
МЕСТО      find_folder / fs_list — где это лежит на самом деле
ПОПАСТЬ    open_folder (окно проводника поднимается в фокус)
ПРОВЕРИТЬ  fs_list после действия: файл действительно там, где сказано
ИНАЧЕ      не нашла — сказать, где искала, а не выдумывать путь
```

### Браузер
```
МЕСТО      свой браузер или его? chrome_state / attach_chrome
ДЕЙСТВИЕ   search_list -> показать пронумерованные результаты
ПОПАСТЬ    open_result(N) по выбору человека
УБЕДИТЬСЯ  show_passage — подсветить и прокрутить к нужному месту
ИНАЧЕ      реклама поверх -> close_ad; не грузится -> другой результат
```

### Медиа
```
ДЕЙСТВИЕ   media(play/pause/next) — глобальные клавиши, фокус не нужен
ПРОВЕРИТЬ  слух (hearing): звук действительно появился или пропал
```

### Игра
```
ПОПАСТЬ    window_focus — без фокуса игра не примет ни одной клавиши
УБЕДИТЬСЯ  окно впереди (проверка обязательна: игры любят терять фокус)
ДЕЙСТВИЕ   key_press
ИНАЧЕ      игра не отдаёт элементы (screen_read пуст) — это нормально,
           работать только клавишами
```

## 4. Три правила, которые ломали всё

1. **Не рапортовать о том, чего не проверила.** «Закрыла» говорится только
   после того, как окно исчезло из `window_list`. До проверки — «пробую».
2. **Подтверждение — отдельный шаг.** Набранный текст без Enter = ничего
   не произошло.
3. **Провал не повторяют, провал обходят.** Второй одинаковый вызов с теми
   же аргументами — признак зацикливания (сторож это уже ловит). Не вышло
   через UIA — идти клавишами; не вышло клавишами — сказать честно.
