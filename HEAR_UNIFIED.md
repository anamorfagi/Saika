# ANAMORF · Единый слуховой тракт
## «худший микрофон → кто, что и какой частотой сказал»

Дизайн-документ. Как из самого всратого звука с микрофона (тихого, шумного,
с эхом, с чужими голосами из колонок) получить: чистый отстроенный сигнал →
чёткие слова → частоту/тембр → **чей это голос** → и, поверх, семантически
восстановленное «что всё-таки было сказано».

Документ опирается на разбор реального кода: `stt/frontend.py`,
`stt/manager.py`, `stt/neuro_vad.py`, `stt/engines.py`, `stt/turns.py`,
`stt/unmix.py`, `stt/voice_dna.py`, `voiceprint/*`, `denoise.py`,
`hearing.py`, `misheard.py`, `stt/rescore.py`, `sound_map.py`, `clap_ears.py`
и участков конвейера в `main.py`.

---

## 0. Диагноз: почему сейчас разваливается на плохом звуке

Одна ошибка объясняет почти все жалобы («распознаватель как будто не
работает», «частоты видит, а людей не заводит», «звук слышу, но не считаю
голосом»).

**Выравнивание громкости стоит не там.** `frontend.prepare()`
(DC-rez → HPF 70 Гц → компрессор → AGC до −20 dBFS → look-ahead лимитер)
применяется **только к собранной фразе прямо перед движком STT**. А два
других потребителя — **ворота речи (VAD)** и **кодировщик голоса (ECAPA)** —
получают **сырой звук**, у тебя это ≈ −46 dBFS (rms ≈ 0.005).

Последствия, каждое подтверждено кодом:

- **VAD бракует речь.** `VadSegmenter` (`stt/manager.py`) считает порог по
  сырому уровню; `neuro_gate_rms = 0.0025` и `gate_min = 0.004` — абсолютные
  величины. Тихая реальная речь 0.005 болтается на самом полу → «звук слышу,
  но не считаю голосом», «Отброшено окон: N».
- **ECAPA даёт химеры.** `voiceprint/__init__.py::_process()` кодирует
  **сырой** `win` (`pcm = clip(win*32768); enc.encode(pcm)`), громкость НЕ
  нормируется (нормируется только выходной вектор). Амплитуда сдвигает
  эмбеддинг → у разных людей вектора сближаются → кластеры не расходятся →
  карточки не заводятся, «переезды» между голос А/В.
- **Движок при этом видит выровненный звук** → текст идёт. Поэтому снаружи
  «распознаёт, но всё остальное сломано»: асимметрия прячется.

Второй системный дефект — **знакомство с голосами не умеет диаризовать
смесь.** `auto_meet` (`voiceprint/__init__.py`) — это «один незнакомец за
раз по одному центроиду»: `c = mean(S.unk)`, `keep = X[X@c > 0.45]`,
`enroll("Голос N", keep)`. Если в `S.unk` намешаны 4 голоса, `c` — их общий
центр, порог 0.45 рыхлый, `keep` втягивает всех четверых, и рождается **один**
«Голос N» = блин из четырёх. Плюс `S.unk = []` на любом совпадении и гвардия
`no_meet_while_media` — накопить чистую четвёрку почти невозможно.

Вывод: **сначала чиним фундамент (уровень до ворот и до ECAPA), потом
диаризацию (кластеризация вместо одного центроида), потом надстраиваем
семантику (LLM: что сказано + кто).** Ниже — единый тракт из шести ступеней.

## 1. Архитектура: одна технология, шесть ступеней

```
 сырой чанк (mic/sys, 100 мс, int16@16к)
        │
 ┌──────▼─────────────────────────────────────────────────────────┐
 │ Ст.0  КОНДИЦИОНИРОВАНИЕ ЗАХВАТА (новое, ОБЩИЙ фронт, на потоке)  │
 │  DC-rez → HPF 70 → capture-AGC (медленный, речевой RMS, cap 24дБ)│
 │  → мягкий Wiener (floor 0.08)                                    │
 │  ОДИН выход кормит ВСЕХ: ворота, ECAPA, PANNs-уши, буфер фразы   │
 └──────┬───────────────┬───────────────┬─────────────────────────┘
        │               │               │
 ┌──────▼──────┐ ┌──────▼───────┐ ┌─────▼──────────┐
 │ Ст.1 VAD    │ │ Ст.2/3 ГОЛОС │ │ уши/шум-карта  │
 │ +смена      │ │ ECAPA→онлайн │ │ (как сейчас)   │
 │ говорящего  │ │ кластеры→ID  │ └────────────────┘
 └──────┬──────┘ └──────┬───────┘
        │ фраза         │ стабильный speaker/track
 ┌──────▼───────────────▼──────────────────────────────┐
 │ Ст.4 ТРАНСКРИПЦИЯ                                     │
 │  frontend.prepare(фраза) → turns.split → [unmix] →   │
 │  GigaAM → слова+тайминги+conf                         │
 └──────┬───────────────────────────────────────────────┘
        │ окно последних сегментов (текст+speaker+conf+время)
 ┌──────▼───────────────────────────────────────────────┐
 │ Ст.5 СЕМАНТИКА (LLM, оконный, single-flight)          │
 │  «что всё-таки было сказано» + разнести по дорожкам   │
 │  правит слова (гард фонетическим ключом) и низко-      │
 │  уверенные метки говорящего по логике диалога         │
 └───────────────────────────────────────────────────────┘
```

Ключевой принцип: **акустика — основа, семантика — верхний свидетель.**
Голос (ECAPA/тембр) — истина про «чей», LLM ломает только спорные случаи и
чинит слова, но не смеет менять смысл (гард фонетическим ключом).

## Ступень 0 — Кондиционирование захвата (фундамент, самое важное)

**Проблема:** ворота и ECAPA видят −46 dBFS.
**Решение:** один лёгкий предобработчик на потоке (100 мс чанки), чей выход
кормит ВСЕХ потребителей, а не только движок.

Цепочка (переиспользуем проверенные примитивы из `frontend.py`, не изобретаем):

1. **DC-rez** — `x -= mean(x)` (дешёвые платы дают смещение).
2. **HPF 70 Гц** — `_highpass_fft` (убрать гул/50 Гц, чтобы они не задавали
   нормировку).
3. **Capture-AGC** — МЕДЛЕННАЯ, непрерывная (в отличие от фразовой мгновенной):
   - оценка уровня по **речевым кадрам** (`_speech_rms`: кадры ≥ 0.2·peak),
     чтобы не тянуть вверх фон/тишину;
   - цель −23…−20 dBFS, **жёсткий потолок усиления `max_gain_db ≈ 24 дБ`**,
     длинная постоянная времени (обновление раз в 100 мс), без «дыхания»;
   - это и есть «отстройка тихого звука» до того, как его судят ворота и
     кодировщик.
4. **Мягкий Wiener** (`_Wiener`, decision-directed, `floor 0.08`) — чистим
   ПОСЛЕ выравнивания, чтобы оценщик шума видел реальные амплитуды. Мягкий и
   с ненулевым полом — сохраняет тембровые признаки, на которые смотрит ECAPA.
   **Не ставить агрессивный gate перед ECAPA** — он зануляет тихие озвонченные
   хвосты, несущие личность голоса.

**Куда это встроить (конкретно):**
- Новый модуль `anamorf/stt/capture.py` (или третий сиблинг `Denoiser`),
  функция `condition(pcm16)->pcm16`, вызывается в `_hear_worker` (`main.py`)
  РАНЬШЕ, чем `hearing.feed`, `voiceprint.feed` и запись в `stt.vad`.
- Порядок в горячем цикле: `p = condition(p)` сразу после снятия лага, до
  веток mic/sys. Тогда `DENOISE` (потоковый) может стать частью Ст.0 или
  идти следом.
- Движок STT продолжает свой `frontend.prepare(фраза)` — AGC там
  самонаводящаяся (второй проход почти единичный), но **компрессор из
  prepare на уже сжатом Ст.0 лучше ослабить/выключить**, чтобы не пережать
  динамику дважды (окончания слов — то, что «дописывается наугад»).

**Что это чинит:**
- (a) ворота видят −20 вместо −46 → `gate_min/gate_ratio` работают как
  задумано, меньше реальной речи в брак;
- (b) ECAPA получает энергонормированную речь → вектора расходятся → люди
  начинают отделяться;
- (c) картинка UMAP из «двух размытых облаков» превращается в кластеры.

**Риски и предохранители:**
- AGC поднимает и шум: жёсткий cap усиления + оценка по речевым кадрам +
  Wiener ПОСЛЕ уровня.
- Не гейтить сигнал, идущий в ECAPA (гейт — только для решения VAD).
- Стоимость: capture-AGC почти бесплатна; Wiener добавляет ~32 мс окна
  задержки на потоке — приемлемо.

**CFG (новые):** `hear.capture.enabled`, `hear.capture.target_dbfs=-22`,
`hear.capture.max_gain_db=24`, `hear.capture.denoise="wiener"`,
`hear.capture.attack_s`, `hear.capture.release_s`.

## Ступень 1 — VAD и сегментация (на кондиционированном звуке)

Инфраструктура готова, нужно снять костыли и добавить границу по говорящему.

- **`VadSegmenter`** (`stt/manager.py`): режет фразу по паузе (адаптивный
  `need_ms`: 700 мс → 100 мс по мере длины) и по потолку `max_segment_s=12`.
  Neural VAD (Silero, `neuro_vad.py`) отвечает только на «это речь?».
- **Что улучшить:**
  1. Пороги теперь считаются по кондиционированному звуку → адаптивную
     подстройку порога можно вернуть без риска задушить тихую речь.
  2. **Новая граница `end_by_speaker_change`** рядом с `pause`/`length`:
     закрывать фразу на смене доминирующего эмбеддинг-кластера (см. Ст.2),
     даже без паузы. Это чинит «перебивают без пауз → нож на 12 с посреди
     диалога». Причина реза записывается как `last_cut="speaker"`, чтобы GLUE
     не клеил куски разных людей.
  3. **Прокинуть метаданные сегмента:** сейчас `transcribe_segment` отдаёт
     `{text, engine, words}` и **выбрасывает тайминг и говорящего**. Вернуть
     `t0/t1` (абсолютное время в сессии) и `cut_reason` в самом dict —
     это опора для Ст.5.

**CFG:** `stt.vad.speaker_cut=true`, `stt.vad.speaker_cut_hold_ms`.

## Ступень 2 — Диаризация (акустика): turns + unmix + онлайн-кластеры

Три механизма, каждый на своём месте; главный пробел — глобальная
кластеризация.

- **`turns.split`** — режет ПОСЛЕДОВАТЕЛЬНУЮ смену тембра внутри фразы
  (питч-первым, потом ECAPA-косинус `<0.35`, потом тонкая сетка по voice-DNA
  `<0.82`), помечает `crowd=True` при одновременной речи. Двухсвидетельная
  схема (тембр+питч) — сюда же логично войдёт третий, семантический,
  свидетель (Ст.5, шов A).
- **`unmix.split`** — SepFormer (`whamr16k`) разделяет ОДНОВРЕМЕННЫЕ голоса на
  crowd-кусках. Предел: 2 говорящих, 0.8–10 с, ленивый прогрев на простое GPU.
- **ПРОБЕЛ — нет глобальной кластеризации людей.** Каждая фраза диаризуется в
  одиночку; `who()` матчит к реестру независимо; сквозной «Спикер A/B/C»
  через разговор не держится. Плюс `auto_meet` из одного центроида не умеет
  разложить смесь (см. §0).

**Что построить — онлайн-кластеризацию эмбеддингов (замена `auto_meet`):**
1. Держать **N кандидат-центроидов**, а не один (leader/DP-means или онлайн
   k-means): новый эмбеддинг ищет ближайший центроид; если `max cos <
   link_thr` — **рождается новый кластер**, а не вливается в среднее.
2. **Не сбрасывать `S.unk` на каждом матче** — кластеризатору нужен
   непрерывный поток.
3. **Батч-вариант** на `len(S.unk) >= need`: HDBSCAN / агломеративная по
   косинусу, число кластеров по eigengap/силуэту → каждый кластер ≥ min-size
   и с достаточным зазором enroll-ится своим «Голос N».
4. **Критерий рождения кластера** — переиспользовать двустороннюю логику
   паспорта (`own_lo/imp_hi/gap`), чтобы не плодить дубли.
5. **Только ECAPA (192-d), не лёгкий (68-d).** У лёгкого разные люди дают
   косинус ≈0.7 при своих ≈0.83 → окно разделения ~0.1, кластеризация смеси
   почти безнадёжна. У ECAPA размах шире (`_floor 0.45`) — есть где работать.
6. **Одновременную речь — через `unmix` ДО эмбеддинга**, иначе смешанные окна
   всегда сидят между кластерами и портят центроиды.

**Итог ступени:** стабильные `speaker`/`track`, живущие сквозь фразы, а не
локально. Плюс `end_by_speaker_change` для Ст.1.

**CFG:** `voiceprint.cluster.mode="online|batch"`,
`voiceprint.cluster.link_cos`, `voiceprint.cluster.min_size`,
`voiceprint.cluster.min_gap`. Гвардию `no_meet_while_media` заменить на
«медиа-источник помечает кластер тегом `sys/stream`, но люди всё равно
заводятся» (см. дорожную карту твоих цифровых личностей: твич/дискорд-карты
с пониженным базовым доверием).

## Ступень 3 — Идентификация голоса (частота + чей)

- **Частота/тембр уже есть и хороши:** `_f0` (автокорреляция с октавной
  коррекцией, 65–320 Гц), `voice_dna.envelope` (кепстральный отпечаток,
  инвариантный к высоте — тот же человек октавой выше остаётся собой),
  `formants`+`tract_length` (физический размер тракта → взрослый/ребёнок/
  муж/жен как приор). Это и есть «определять частоту».
- **Кто:** `registry.match` — косинус к центроиду со самокалиброванным
  порогом `mu-2.5·sd` (или порог из паспорта, посчитанный против чужих).
- **Что улучшить на чистом входе (Ст.0):**
  - пороги перестанут «плыть» от громкости → меньше ложных «переездов»;
  - `adapt` (дописывание эталона живой речью) станет безопаснее — меньше риск
    отравить центроид тихой химерой;
  - паспорт голоса (7 шагов: тихо/громко/далеко/быстро…) даст честный `gap`.
- **Сквозная непрерывность дорожек** — из Ст.2 (кластеры живут через разговор).

## Ступень 4 — Транскрипция (что за слова)

Оставляем как есть, с одной правкой на стыке с Ст.0.

- `frontend.prepare(фраза)` → `turns.split` → (crowd) `unmix.split` →
  `GigaAM v3 RNNT` (пунктуация, русский SOTA, читает аудио сам). У
  faster-whisper есть словные тайминги+conf — используем в Ст.5.
- **Правка:** т.к. Ст.0 уже выровнял и слегка сжал, компрессор внутри
  `prepare` ослабить (`comp_ratio→1.3` или off), AGC оставить (самонаводится).
  Пэддинг тишины и лимитер — оставить.
- Джанк-фильтр Whisper-галлюцинаций (`_is_junk`) — как есть.

## Ступень 5 — Семантика: «что всё-таки было сказано» + кто (LLM)

Здесь живёт то, что ты просишь: «читать между строк», «что всё-таки было
сказано», и разнос по дорожкам логикой, а не только акустикой.

**Что уже есть:**
- `misheard.*` — чинит слова В СТОРОНУ словаря проекта (фонетический ключ +
  Левенштейн), помечает «шаткие» строки. Чисто эвристика, без смысла.
- `rescore.fix_async` — **единственный уже существующий LLM-проход**:
  локальная модель `chat_once` переписывает подозрительную строку, а
  результат жёстко ограждён **фонетическим ключом** (правка обязана ЗВУЧАТЬ
  похоже) + лимитами роста/редактирования. Но он **однострочный,
  без говорящих, контекст — плоские 6 строк.**

**Что построить — единый оконный проход «диалог-роутер + реконструкция»:**
Обобщить `rescore.fix_async` с одной строки на **окно последних сегментов**,
которые УЖЕ несут всё нужное (в dict `r`): `text`, `speaker`+`speaker_conf`,
`words[].t0/t1/p`, `sec`, `in_dbfs`, `crowd`/`track`/`unmixed`, `src`, `_env`.

Один LLM-вызов на окно, который:
1. **чинит ASR-путаницу слов** («что всё-таки было сказано») — каждое
   изменённое слово проходит гард `misheard.key` (звучит похоже) и лимит
   `max_edit`, иначе откат. LLM не смеет менять смысл — только
   реконструировать спутанное;
2. **разносит сегменты по говорящим/диалогам** логикой (пары
   вопрос→ответ, смена лица, регистр) — но **перекрывает только
   низкоуверенные акустические метки** (`speaker_conf < stt.router.trust_conf`);
   высокая уверенность голоса — истина, LLM ломает лишь спорное;
3. возвращает структурированный JSON `segment_id → {speaker, text}`.

**Куда встроить (конкретно):** новый `stt/dialog_router.py`, вызов в
`_stt_worker` **после `_join_parts`, перед тегированием/GLUE** (это шов A —
тогда GLUE и нумерованные дорожки наследуют СТАБИЛЬНЫЕ id). Роутер держит
пер-канальный (`seg_src`) кольцевой буфер последних `r` (как `GLUE`),
кластеризует по `r["_env"]`, переписывает `speaker`/`track` до GLUE, и
обновляет `SPEAKERS_RECENT`. UI менять НЕ нужно — поля `src/speaker/
speaker_conf/track/unmixed/crowd/glue` уже рендерятся как параллельные
дорожки/облачка; переключить GLUE на ключ `(seg_src, person_id)` — и получишь
настоящие пер-человек пузыри.

**Латентность (критично — LLM один на STT+TTS+диалог):**
- `chat_once` последователен и уже конкурирует за GPU; `rescore` уже ловил
  «подвисания» → добавил `_GATE` + `min_gap_s`.
- Значит роутер **оконный и троттлится**, а не на каждый сегмент; **слить его
  с `rescore` в один проход** (одна поездка чинит слова И разносит людей).
- Пускать только когда окупается: `≥2` имени в `SPEAKERS_RECENT` за 60 с, или
  есть `crowd/unmixed`, или `speaker_conf` низкий. Моно-разговор — пропускать.
- Всё асинхронно, замена текста на месте (как rescore), жёсткий кап
  окна/токенов (урок SepFormer: цена ~квадратично от длины).
- Аудит: событие «было→стало / переразнесено», один килл-свитч
  `stt.router.enabled`.

## Порядок внедрения (что строить первым — по отдаче)

1. **Ст.0 Кондиционирование захвата.** Самый высокий рычаг: одним движением
   лечит ворота, ECAPA-разделение и качество распознавания. Низкий риск.
   ← начать здесь.
2. **Ст.2 Онлайн-кластеризация** (замена `auto_meet` из одного центроида) +
   форс ECAPA. Даёт реальные отдельные карточки людей на чистом входе.
3. **Ст.1 `end_by_speaker_change`** + прокидка `t0/t1/cut_reason` в dict.
4. **Ст.5 Единый LLM-проход** (rescore+router) — «что сказано» и разнос по
   дорожкам. Строить последним: опирается на чистые метки Ст.0–3.
5. Полировка: паспортные пороги, теги медиа-источника вместо гвардии,
   3-й (семантический) свидетель в `turns` (шов A).

Каждую ступень — с замером: `hear_bench` (сырое vs обработанное, WER
до/после), проверка разделимости эмбеддингов (не только дБ).

## Риски и общие предохранители

- **Переобработка вредит.** Агрессивная нейрочистка/усиление может поднять
  WER (модель обучена на живой чуть-шумной речи). Правило: мягко, с замером,
  Wiener ≥ агрессивных гейтов на ветке ECAPA.
- **AGC усиливает шум** — cap усиления + речевой RMS + чистка после уровня.
- **LLM не смеет менять смысл** — гард фонетическим ключом на каждое слово.
- **GPU один** — Ст.5 троттлить и сливать в один проход.
- **Лёгкий кодировщик 68-d непригоден для кластеризации смеси** — только ECAPA.

## TL;DR

Худший микрофон побеждается не одним «мощным шумодавом», а **правильным
порядком**: сначала **выровнять и мягко почистить звук ДО ворот и ДО
кодировщика голоса** (Ст.0 — сейчас этого нет, и это корень всех бед), затем
**кластеризовать голоса онлайн** вместо «одного центроида» (Ст.2), и лишь
поверх чистых меток пустить **один оконный LLM-проход**, который и чинит
«что всё-таки было сказано», и логикой разносит реплики по людям (Ст.5).
Акустика решает «чей голос», семантика — только ломает спорное и
восстанавливает спутанные слова, не трогая смысл.
