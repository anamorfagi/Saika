# Git: ветки и синхронизация между ПК (и с другом)

## Зачем ветки
Ветка — отдельная линия правок. Пока ты в своей ветке, чужой `dev` не ломается.
Слил, когда готово. Конфликт бывает только там, где ДВОЕ правили ОДНИ строки.

## Одна ветка от начала до конца
```
git checkout -b feature-buttons     # создать ветку от текущей
git add -A
git commit -m "что сделал"
git push -u origin feature-buttons  # первый пуш (привязка); дальше просто git push

# слить, когда готово:
git checkout dev
git pull                            # свежий dev
git merge feature-buttons           # влить свою работу
# конфликт? git покажет <<<<<<< в файлах — поправь, затем:
git add -A && git commit
git push
```

## Синхронизация дом ↔ работа
Оба ПК с несинхроненными правками:
```
# ДОМА (где правки не запушены):
git checkout -b home-2026-07-17
git add -A && git commit -m "домашние доработки"
git push -u origin home-2026-07-17

# НА РАБОТЕ:
git fetch
git checkout dev
git merge origin/home-2026-07-17    # вливаешь домашнее
# правишь конфликты (если есть), git add -A && git commit
git push
```
В интерфейсе Сайки кнопки ⬆ (закоммитить+запушить) и ⬇ (подтянуть) работают с
ТЕКУЩЕЙ веткой. Переключение веток пока делается в терминале (см. выше).

## Совместно с другом
- Друг работает в СВОЕЙ ветке → делает Pull Request на GitHub → ты смотришь и
  жмёшь Merge. Так его правки не сваливаются тебе внезапно.
- Пулль перед началом работы, коммить маленькими кусками — конфликтов меньше.
- Никогда `git push --force` в общую ветку — затрёшь чужие коммиты.
- Не редактируйте вдвоём один файл одновременно. У нас крупный `index.html` —
  договоритесь, кто его трогает, либо разнесите на модули.

## Подключить второго разработчика (с нуля)

### Ты (владелец) — добавить друга на GitHub
1. Репозиторий на GitHub → **Settings** → **Collaborators** → **Add people**.
2. Ввести его GitHub-логин/почту → **Add to repository** (право Write).
3. Друг принимает приглашение (почта / github.com/notifications).

### Друг — настроить проект у себя
Его старая присланная папка обычно НЕ git-репозиторий. Проще клонировать заново:
```
git clone https://github.com/ВЛАДЕЛЕЦ/РЕПО.git
```
Новичку — поставить **GitHub Desktop** (всё мышкой). Модели/venv не в git —
доустановятся при первом `start.bat`. Старую папку оставить как бэкап.
Дальше — своя ветка:
```
git checkout -b feature-друг
git add -A && git commit -m "что сделал"
git push -u origin feature-друг
```

### Влить его работу
1. Друг на GitHub жмёт **Compare & pull request** → создаёт PR из своей ветки в `dev`.
2. Ты открываешь PR, смотришь diff (зелёное/красное) → **Merge pull request**.
3. У себя: кнопка ⬇ в Сайке или `git pull`.

Если в старой папке друга были ценные правки — перенести их вручную (копией
файлов) в свежий клон: старая папка с GitHub не связана.

## Полезное
```
git status              # что изменено / в какой ветке
git branch              # список веток (звёздочка = текущая)
git checkout dev        # переключиться на ветку
git log --oneline -10   # последние коммиты
git merge --abort       # отменить неудачный merge и вернуться как было
```

## Дев-доска
Прогресс проекта — в `devboard.json` (+ авто-генерится `DEVBOARD.md`). Оба файла
в git, поэтому синкаются между ПК и их прочитает другая нейронка, которой отдашь
проект. Редактируется из панели 🗺 в интерфейсе Сайки.
