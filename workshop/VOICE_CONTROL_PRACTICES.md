# Практики голосового управления ПК — что берём у зрелых проектов

> 2026-07-28. Разбор по просьбе владельца: «найдём проекты для управления ПК
> голосом и применим их практики». Смотрели три семейства: голосовые
> грамматики (Talon, Numen), агентные системы Windows (Microsoft UFO/UFO2),
> зрение-в-клики (OmniParser V2). Здесь — вытяжка практик и их судьба у нас:
> ЕСТЬ / ВЗЯТО СЕЙЧАС / ДОРОЖНАЯ КАРТА.

## Семейство 1: голосовые грамматики (Talon, Numen)

Talon — золотой стандарт hands-free работы за ПК. Ключевая идея: **не
распознавать смысл, а слушать короткие командные формы** — это даёт скорость
и надёжность, недоступные LLM.

| Практика | Суть | У нас |
|---|---|---|
| Короткие командные формы | «focus chrome», «launch music» — грамматика, не разговор | ЕСТЬ: рефлексы (server/reflex.py), <50мс |
| Имена приложений с пользовательскими алиасами (CSV) | человек зовёт программы своими словами | ВЗЯТО СЕЙЧАС: pc.window_aliases в config поверх встроенных |
| Цепочки команд без пауз | «go up fifth», связки форматтеров | ВЗЯТО СЕЙЧАС: «сверни всё и открой проводник» — рефлексы цепочкой через « и / потом / затем » |
| Режимы sleep/command/dictation | команда против диктовки | ЧАСТИЧНО: у нас руль другой — рефлекс ловит команду, остальное разговор. Отдельный «режим диктовки» — в карту |
| Mouse grid / числовые оверлеи | клик без мыши: сетка или номера элементов | ДОРОЖНАЯ КАРТА (см. клики ниже) |

Вывод Talon для нас: рефлексный слой — правильная архитектура, его надо
РАСШИРЯТЬ грамматикой (числа, повторы, цепочки), а не тащить всё в LLM.

## Семейство 2: агентные системы Windows (UFO / UFO2, COLA)

UFO2 (Microsoft, «Desktop AgentOS») — самое зрелое из открытого. Практики:

| Практика | Суть | У нас |
|---|---|---|
| Гибридное обнаружение элементов: UIA + зрение | сначала Accessibility-дерево Windows (точно, дёшево), зрение — только где UIA слеп | ДОРОЖНАЯ КАРТА №1 — это и есть «найти и тыкнуть» |
| Единый слой GUI+API действий | если у приложения есть API — звать его, клик только как фолбэк | ЕСТЬ по духу: инструменты (window_*, volume, folders) и есть тот самый API-слой |
| Спекулятивный мультиплан | несколько действий за один вызов LLM | ЧАСТИЧНО: текст-протокол исполняет до 2 маркеров за ответ; расширить до плана — в карту |
| HostAgent + AppAgent'ы | разбиение: диспетчер задачи + специалисты по приложениям | АНАЛОГ: «быстрое мышление» (роутер) + эскалация в облако; спец-агенты по приложениям — в карту |
| Изоляция Picture-in-Picture | агент работает в отдельном виртуальном рабочем столе, не мешая человеку | ДОРОЖНАЯ КАРТА (дальняя): интересно для длинных задач |
| Предохранители на опасное | подтверждения по классу риска | ЕСТЬ: trust.py (риск 1-5) + прямая просьба/«да» = согласие |

## Семейство 3: зрение → клики (OmniParser V2)

OmniParser превращает скриншот в СПИСОК элементов с координатами и
подписями — «глаза для кликов» любой LLM. Практика для нас:

- шаг 1 всегда UIA (pywinauto/uiautomation): дерево элементов активного окна
  бесплатно и точно — кнопки, поля, их имена и координаты;
- шаг 2, если окно «слепое» для UIA (игры, канвас-редакторы) — кадр экрана
  через уже существующее зрение + разметка элементов (OmniParser-подход);
- клик — SetCursorPos+SendInput по координатам из шага 1/2; риск 4 в trust.

Это ровно недостающий инструмент `ui_click` из фразы владельца «вижен могла
активировать, найти и тыкнуть».

## Дорожная карта (по убыванию отдачи)

1. **`ui_list` + `ui_click` через UIA** — дерево элементов активного окна и
   клик по имени элемента («нажми Сохранить»). Библиотека uiautomation/
   pywinauto, ставится через ensure_features. Зрение НЕ нужно для 90% окон.
2. **Числовые оверлеи** (Talon/Vimium-стиль): «покажи номера» → поверх
   элементов активного окна рисуются числа, «тыкни 7». Устойчиво к ошибкам
   распознавания имён.
3. **Спекулятивный план**: текст-протокол принимает 3-5 маркеров за ответ и
   исполняет как последовательность с проверкой после каждого шага.
4. **Режим диктовки**: «пиши: …» → текст летит в активное окно клавиатурой
   (SendInput), «хватит писать» — выход.
5. **PiP-изоляция** (дальняя): длинные задачи агент делает на втором
   виртуальном рабочем столе.
